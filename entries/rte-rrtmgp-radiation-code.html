RTE+RRTMGP radiation code (CESM3, E3SM, ICON)

Fixed – releasedcodeSignificance: High

What it is

RTE+RRTMGP is the radiative-transfer code that computes how sunlight and infrared radiation are absorbed and emitted by gases, clouds and aerosols. It is the radiation scheme in several major climate models, including CESM3, E3SM and ICON.

Finding

6 interpolation/indexing bugs; worst (#425, in every release since v1.0) lets a zeroed gas keep absorbing, understating CO2-removal effects 70–80%

Summary

RTE+RRTMGP is the radiation code in CESM3 (CAM7), E3SM and ICON. We found six indexing and interpolation errors. The important one, issue #425, was in every release from v1.0 (2019) to v1.9.3. When a key absorbing gas is set to exactly zero, the gas-optics interpolation reads the absorption table one node short, so the "removed" gas keeps absorbing. A clear-sky test understates CO2's radiative effect by 70–80%. The bug is fixed in release v1.10 (16 November 2026).

What we found

  • #425, zero key gas. RRTMGP interpolates absorption between pairs of key species using a mixing fraction η. When the second gas of a pair is exactly zero (η = 1), the interpolation weight is computed from the wrong table node. This affects both the CPU and GPU kernels.
    • Longwave triggers: CO2, O3, CH4 or N2O set to zero. Shortwave triggers: CO2, CH4 or O2 set to zero.
    • The radiative effect of removing a gas is understated. In a clear-sky test: CO2 by 70%, CH4 31%, N2O 8%, O3 6%. On a tropical RCEMIP column: longwave CO2 82%, CH4 58%, N2O 17%, O3 46%; shortwave O2 57%, CO2 58%.
    • An underflowing value acts like a zero: the RCEMIP ozone profile triggers the bug below about 440 hPa (a small effect, OLR −0.27 W m−2). The fix changed the reference answers of the standard longwave RCE example.
  • Five smaller errors (#424, #426, #427, #428, #429) in options that production climate runs of CAM7 and E3SM do not use. #424, #426 and #428 are fixed; #427 and #429 remain open and are low-impact.

Why it was not caught

The standard benchmark (RFMIP-IRF) never sets a gas to zero: its perturbations are pre-industrial levels and scaled CO2. So the trigger was never tested.

Who is affected

  • Exposed: greenhouse-effect attribution by removing gases; "no-CO2", "no-ozone" or "no trace gas" experiments in E3SMv2/v3, CAM7/CESM3 and ICON; idealized RCE, aquaplanet and LES setups that zero CH4, N2O, O3 or O2 (ICON's RCE scripts set O2 = 0, and its default is irad_o3 = 0); emulators trained on zero-gas cases; forcing of a gas from zero.
  • Not exposed: standard CMIP DECK and scenario runs, RFMIP comparisons, and 4×CO2 forcing at present-day gas levels.
  • We have not yet found a published paper confirmed to have run a gas-removal experiment with RRTMGP.
  • E3SM's C++ port contains the same logic; whether it has been fixed was not checked.

Response

The developers fixed #424 and #428 on 11 November (PR #431), #426 on 15 November, and #425 on 16 November (PR #437, with an updated longwave RCE reference in rrtmgp-data #14). Release v1.10 ships the fixes.

What users can do

Upgrade to v1.10 or later, and check model tags that pin earlier versions. Rerun any experiment that set a key gas to zero.

Reproduce

Report with tests before and after each fix: doi:10.5281/zenodo.23486714. Issues: #425 and #424–#429.
