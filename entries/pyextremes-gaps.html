pyextremes: missing data biased return values low

Fixed and released (v2.7.0)codeSignificance: Medium
Targetgeorgebv/pyextremes, the main Python library for extreme-value analysis (flood, coastal, rainfall and wind design levels). Checked at v2.6.1 / master 89d73c9.

Reported12 Nov 2026, issue #123
OutcomeFixed by pull requests #124, #125 and #126, merged 21 Nov 2026 and released in v2.7.0.
Fixed on2026-11-22 (released)
Fixed inv2.7.0 (PRs #124–#126, merged 21 Nov 2026 HST)
Affected versionsv2.6.1 and earlier

What was wrong

Real station records almost always have gaps. pyextremes handled them in ways that pushed estimated return values (for example the "100-year" level) too low, which is the non-conservative direction for design:

  1. Peaks over threshold: the event rate used the calendar span, not the time actually observed. Missing stretches were counted as observed time, so the rate of extreme events was underestimated. The diagnostic plots used the same rate, so they did not reveal the problem.
  2. Block maxima: partly observed blocks counted as full blocks. A year with two weeks of data contributed an "annual" maximum like any complete year. Only the last block could be screened.
  3. Block maxima with errors="coerce": empty blocks were filled with the mean of the other maxima, which narrowed the fitted spread and the confidence intervals.

Evidence (Monte Carlo, 100 simulations)

Synthetic daily data with a known answer: true 100-year level 10.51.

CaseMean 100-yr levelBias
Peaks over threshold, full 60-year record10.36−0.14
Same, 24 consecutive years missing (40%)9.84−0.67 (the reported "100-yr" value is about a 51-yr level)
Block maxima, 14 of 60 years only ~5% observed9.76−0.74
Block maxima, 15 empty years, errors="ignore"10.46−0.04 (95% CI coverage 0.90)
Same, errors="coerce"9.60−0.90 (95% CI coverage 0.61)

The fix

  • New observed_duration option for peaks over threshold, so the event rate uses the time actually observed (#125).
  • New min_block_count option for block maxima, applied to every block, so sparsely observed blocks can be excluded (#126).
  • Documentation of gappy records in the user guide (#124).

Users of earlier versions with gappy records should rerun their analyses with v2.7.0 or later and set these options.
